## Existing architecture and integration

`GridBoard.MoveWithExits` validates gate color, full footprint and the entire swept path,
then removes occupancy and the block once, returning an immutable ExitPlan. Its gate edge,
StartAnchor and fully outside EndAnchor are the source of presentation coordinates.
`PuzzleSession.MoveTowards` immediately reaches Won on the last logical exit. These models
and their rules are unchanged.

GameplayController already owned one exiting view, an unscaled clock, disabled departing
colliders and a default 0.3-second root interpolation. Its `IsPresentingExit` property gates
new interaction and `CampaignController.CanNext`. M4.5 uses that same clock and completion
gate. It does not start a second coroutine, subscribe another exit listener, or postpone
logical removal. The default M0–M4 path remains the existing 0.2–0.4-second presentation.

The optional SoftCubeBurst is built on the inactive runtime level hierarchy before it is
activated. It reads the successful ExitPlan and the view's actual footprint. Failed and
ordinary movement do not start it. Duplicate starts are rejected. Completion, cancellation,
disabled/destroyed effects and a destroyed departing view all release the existing exit
gate safely; no independent pending-effect counter exists.

## Animation design

- **0.00–0.18 seconds:** move the intact original shape along the accepted straight exit
  path using smoothstep. North is +Z, South −Z, East +X and West −X. The full shape reaches
  the already validated outside EndAnchor before fragmentation.
- **0.18–0.48 seconds:** hide all original renderers, including contact shadows, and create
  exactly **10** miniature rounded cubes. Their centers are distributed among occupied
  footprint cells with at most 0.16-cell XZ jitter, not the shape's bounding-box center.
  L-shaped pieces therefore do not originate fragments in the empty corner.
- Fragments use the shared M4 RoundedBox mesh and the actual block's shared material.
  Size is 0.23–0.29 cells; outward travel 0.12–0.24 cells; lateral travel at most 0.20 cells;
  upward arc 0.16–0.22 cells plus a 0.04-cell rise. Rotation is mild, at most 35 degrees
  per axis. Cubic ease-out handles translation/rotation; progressive scale reaches zero.
- Stable integer hashing supplies the variation. Unity's global Random state is untouched.
  The supplied trajectory validation includes rotation-independent bounds at both extremes
  of matching gate apertures, using the actual serialized level dimensions and camera.

There is at most one active burst with ten fragment GameObjects per gameplay controller.
Fragments have only Transform, MeshFilter and MeshRenderer. They have no Collider,
Rigidbody, block view or drag input. They use opaque approved materials without per-piece
material instances, transparency, physics, particle packages or new shaders. Tiny-fragment
shadow casting/receiving is disabled. Each frame reuses existing arrays and structs.

A single owned root is removed on completion/cancellation. In Play Mode it is hidden
synchronously and Destroy finishes at frame end; EditMode cleanup uses DestroyImmediate.
No pool or VFX manager is introduced. The screen-space overlay HUD remains in front.

## Synchronization and cleanup

The old M4 child shrink is bypassed only when the optional burst is enabled. Selection
highlight/lift remains. Only the new experience defers terminal HUD visibility while its
burst is pending; logical Won/Failed states and timers are unchanged. Next continues to
use the accepted CanNext guard and cannot advance before completion. The normal result
card/reveal and button appearance are preserved. Nonfinal timers continue advancing during
presentation, as before; the extended lock lasts 0.48 seconds instead of 0.3 seconds.

Restart calls the burst cancellation before the existing Session.Restart, board adoption,
view reactivation and collider restoration. Cancel restores captured renderer enabled
states, hides/removes fragments and clears references. Owner disable/scene retirement also
cancels through the existing FinishExit. Disabling only the burst cancels immediately and
the controller finishes the pending exit on its next presentation tick. Repeated cleanup
is harmless. Retiring a level keeps all effect objects in the owning scene hierarchy.

Exit.wav still plays once from the accepted PolishFeedback/PolishCueState movement event.
The burst never emits movement or audio events. Select, Blocked, UiClick, Exit, Win and
Fail assets, source settings, subscriptions and deduplication are unchanged. Win/Fail
audio retains its existing logical-state timing; the new deferral applies to the result UI.

Optional release settling is omitted. SelectionChanged(false) also represents successful
exit, cancellation and focus loss, so it is not an unambiguous normal-release signal.
Adding a pointer lifecycle event solely for this secondary effect was unnecessary.

### Visual-feedback audit: findings and focused corrections

The saved FeedbackCampaign enables `gameplayFeedback` and `softCubeBursts`, references the
actual HUD/reveal, and retains the 1080x1920 overlay Canvas and 15s threshold. Runtime
LevelPresentation constructs enabled PolishedBlockVisual components around the actual
collider-free Soft Visual children; the disabled primitive renderer/collider parents are
not the animation targets. PointerDragController.Update calls the authoritative
GameplayController/PuzzleSession/GridBoard path and emits its MovementResult. PolishFeedback
is bound to the active campaign gameplay and consumes the existing PolishCueState decision.
There is no missing saved flag or absent blocked event in that inspected wiring.

Two independent MovementRequested subscribers previously handled cancellation and the
new Blocked cue. A blocked result may contain accepted steps before its final obstruction.
If PolishFeedback's subscriber ran first (for example after a visual re-enable), it started
the contact and the visual's later subscriber immediately canceled it. The correction routes
Phase B movement observation and the existing cue through one ordered callback, clearing
recovered travel first and then starting a new contact. Legacy M4/Phase A visual subscriptions
remain unchanged when the Phase B flag is false. The audio cue calculation, playback call,
assets and once-per-held-gesture policy are unchanged.

Even with event delivery intact, the old 5.5% compression affected only the 0.46-cell height.
At the accepted 0.68 cell size, 63.435-degree orthographic camera pitch and 6.25 size, its
peak projected height change is approximately 1.18 reference pixels at 1080x1920. The new
contained XZ squash changes projected block width by about 8.70 reference pixels and adds
a warm flash. These are static screen-size estimates, not rendered-frame measurements.
One component continues to own selection lift, exit scaling and contact presentation;
there is no competing per-frame transform writer. Tint snapshots preserve custom properties.
Deselection keeps the new color already applied by GridBlockView instead of restoring a
stale selected tint. Movement and completion restore the captured selected presentation;
Restart/adoption, exit and disable return all cosmetic state safely.

GateGlow also used a raw linear URP material fallback value in MaterialPropertyBlock.SetColor,
which expects sRGB. It now reuses the accepted SoftToyTheme.SelectionSrgb helper, so the
first pulse sample does not darken the gate. Explicit property-block overrides already use
GetColor's sRGB result and remain respected. See Unity's
[SetColor](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MaterialPropertyBlock.SetColor.html)
and [GetColor](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MaterialPropertyBlock.GetColor.html)
documentation. The stronger brightness/height pulse needs no Bloom, emission keyword or
shared-material mutation and retains its original 0.30s envelope and restoration.

The six Win sparkles were 21/27 reference pixels, pale cream/gold and partially faded/scaled
early in the reveal. They are now 44/54 pixels, darker gold/amber, with a 0.85-to-1 scale,
95% peak alpha and slightly larger outward/upward drift. The existing card remains the sole
result presentation and retains its 0.60s reveal and final-burst gate. The owned sparkle root
is explicitly the last card sibling; the inspected scene has no clipping Mask/RectMask2D
on this hierarchy. Stars stay on the upper/side border, clear of buttons, non-raycasting,
and are still removed by the existing completion/reset/disable lifecycle.
