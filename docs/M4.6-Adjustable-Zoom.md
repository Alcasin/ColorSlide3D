# Adjustable gameplay zoom and compact framing

The framing restriction on Levels 1–6 has since been lifted. The current shared
policy and complete before/after table are in [Unified Camera Framing](M4.6-Unified-Camera-Framing.md).
The default/controls and accepted exit presentation below remain historical context.

Let Unity recompile, open the existing FeedbackCampaign and press Play. Keys 7/8
select the maximum 8x11 boards. **Equals / Plus** zoom in, **Minus** zoom out;
the numpad Plus/Minus keys also work. Focus the Game View. Each press changes the
requested multiplier by **0.01**, between **1.00 and 1.25**. Shift+Equals is accepted
for Plus; Ctrl/Alt/Command combinations are ignored. Existing unmodified 5–8
level shortcuts retain their behavior.

## Configuration and ownership

`PortraitCameraFit` remains the sole camera owner. Its Inspector **Large Board
Zoom** configuration defaults to **1.25** for boards taller than 10 cells, currently
Levels 7/8. This final default was visually approved on Level 8 at 1080x1920.
The code default is `BoardFraming.DefaultLargeBoardZoom = 1.25f`.
Change that constant to permanently tune the code default after QA, or author the
Inspector value outside Play Mode. No setup command, generated object or scene
migration is necessary. Camera angle, orthographic projection and logical grid
transforms are unchanged.

The private serialization key is now `largeBoardDefaultZoom`, retaining the same
Inspector label. This lets an already-open Editor pick up 1.25 after recompilation
instead of restoring the old 1.18 value from script-reload state. The accepted
scene assets contain neither zoom key and are unchanged; no Apply step is needed.

Levels 1–6 keep their exact previous framing by default. Explicit Editor key
adjustments use one nonserialized override on the persistent scene camera, so
the chosen multiplier survives 5→6→7→8, retry and Next without resetting it.
It is not stored in PlayerPrefs, campaign progression, scene assets or level data.
Disabling the fitter/ending Play clears the override. The Editor hook also resets
it on a new Play session when domain/scene reload are disabled. Serialized default
configuration stays intact. The override field and methods are `UNITY_EDITOR`-only;
keyboard handling stays in the existing Editor-only shortcuts assembly.

When idle, a key adjustment applies immediately and logs requested/effective zoom
and tray utilization of both the viewport and device safe width. During selection
or an exit, the request queues: the camera holds its previous zoom until that
interaction ends. This avoids changing the pointer's world mapping mid-drag or
moving the camera while a departure/burst is in progress. Pending changes are
identified in the log. There is no production HUD debug UI or new input asset.

## Framing policy and measured results

1.00 is the existing full-departure safe frame. Higher zoom divides that frame's
orthographic size by the multiplier, subject only to **playable board, selected
blocks/contact shadows, gate geometry including peak glow, and authored tray**
visibility. The complete historical exit path is no longer a hard zoom limit.

The camera zooms about the playable center, retaining its baseline viewport
placement where possible, then translates in its image plane only as needed to
keep playable bounds within the HUD/safe-area region. Hard bounds use **32 reference
pixels at each safe side, 72 below and 316 above** (280 HUD + 12 offset + 24 gap),
scaled using the existing CanvasScaler. A 0.2% geometric margin remains. If usable
height or width requires a larger size, effective zoom is lower than requested.
Safe-area/aspect changes recalculate the fit; active VFX never change its bounds.

Both existing 8x11 levels have these full-safe-area measurements:

| Resolution | 1.00 tray width | 1.18 tray width | Default 1.25 tray width | Ortho at default | Cell pitch at default (X / projected Z) |
|---|---:|---:|---:|---:|---:|
| 1080x1920 | 72.295% | 85.309% | **90.369%** | 5.901705 | 110.612 / 98.934 px |
| 1080x2400 | 72.167% | 85.157% | **90.209%** | 7.390248 | 110.416 / 98.759 px |
| 720x1280 | 72.295% | 85.309% | **90.369%** | 5.901705 | 73.741 / 65.956 px |

These are tray fractions of the full viewport (also the safe width in this table).
The logical eight-cell grid span at default 1.25 is **81.935%, 81.789%, 81.935%** respectively;
the tray and grid are different physical sizes. Neither ordinary aspect ratio
requires limiting 1.18 or 1.25. Asymmetric notch cases and strongly height-limited
safe areas are checked separately; the latter deliberately reduce effective zoom
to preserve the board/HUD.

## Deliberate exit-presentation tradeoff

At close zoom, a **successfully exited, logically removed** block can travel
partially beyond the screen during its unchanged 0.18-second outward phase.
Active draggable blocks and gate openings remain visible. Occupancy release,
exit plan/end anchor, matching, timing, interaction gating and the Win HUD wait
are unchanged. The camera never zooms out temporarily for an exit.

At scatter, only the cosmetic fragment root is translated the minimum necessary
in the board's XZ plane to keep the **entire continuous fragment envelope** in the
presentation-safe region (8 reference pixels at the sides, 24 below, same 316
HUD exclusion). Original Y is preserved. Relative paths, rotations, arc, duration,
10-fragment count, materials/colors and sound are unchanged. The whole block still
ends at its authoritative planned position. The burst translation is computed
once at birth and remains fixed, rather than following the camera each frame.
An edge burst can consequently appear closer to its gate/over the outer board
strip when its original location would be off-screen. At 1.00, no origin change
is performed; the original full-trajectory presentation remains available.

## Changed files

- `Runtime/Polish/BoardFraming.cs`: zoom configuration/math, playable bounds, shared
  continuous burst enclosure and cosmetic origin constraint. AABB projection uses
  analytic extrema to avoid allocating eight-corner arrays per burst interval.
- `Runtime/Polish/PortraitCameraFit.cs`: configured/default/temporary zoom, locked
  interaction handling, playable fit, utilization and cosmetic burst positioning.
- `Runtime/Polish/SoftCubeBurst.cs`: optional fitter reference; only the fragment

- `Editor/CampaignPlayModeShortcuts.cs`: Editor-only keys and logs in the existing
  focused Game View/Input System dynamic-update callback.
- `Tests/EditMode/M46CameraPolishEditorTests.cs`: explicitly selects 1.00 for the
  existing full-departure regression; all assertions remain intact.
- Added `Tests/EditMode/M46ZoomTests.cs` and `M46ZoomEditorTests.cs`, with metadata.
- `Tools/M46Verification.cs`: new managed fixture and player-metadata exclusion checks.
- README, earlier camera report's supersession notice, and this document.

Source paths above are relative to `Assets/_ColorSlide/` unless under Tools/docs.

## Validation and Unity QA

The final-default adjustment changes only BoardFraming's default constant,
PortraitCameraFit's private configuration key, the two zoom test fixtures, README
and this report. All **211 existing test cases** remain; none were added or removed.
The tests keep 1.18 as an intermediate adjustment value, assert the new 1.25 default
and explicitly start the deferred-zoom test at 1.18 before requesting 1.25.
Side exits and complete cosmetic burst bounds are checked at 1.25 across all three
resolutions. No exit or VFX implementation/timing changed during finalization.

- Runtime, Android-defined Runtime, Editor and Tests compile against the actual
  installed Unity/package DLLs, C#9 with warnings as errors.
- **155 managed tests pass, zero failures/skips. 211 total cases discovered:** all
  **181 existing cases** remain, plus 20 managed and 10 native regression cases.
- Managed checks cover exact 1.00 preservation, multiplier range/nonfinite input,
  1.18/1.25 projection/size/depth, tray/board/gate envelope, asymmetric safe areas,
  height-limited zoom, successful logical exits and complete translated bursts.
- Compiled native checks cover real renderers/colliders and camera rays, fragment
  origin/relative motion/materials and actual end anchors, deferred selection/exit
  zoom, 5–8 replacement persistence/default reset, nonserialization and real Input
  System keyboard events. Existing first-six framing coverage remains intact.
- The original full-exit regression still tests its complete path at 1.00.
- Android-defined metadata confirms level-selection and zoom QA methods/state are
  absent. Existing Editor assembly remains Editor-only; no new dependency.
- Existing managed witness replay/searches, protected-file hashes, metadata/GUID,
  serialized reference, JSON and diff/whitespace checks are performed.

Native Unity test or Play Mode success is not claimed. Save existing scene edits
before running the full EditMode suite (**expected 211**); native scene tests reuse
the owned scene-copy fixture, restore the previous active scene and remove only
their temporary assets in `finally`. Keyboard tests remove their owned device and
restore the previous current keyboard.

For visual QA: Play FeedbackCampaign, choose Level 8, use Plus/Minus and numpad
keys, check the log and switch 5–8. Check all target resolutions and device safe
areas, gate visibility and touch picks, then the complete edge departures/bursts,
pending adjustments while dragging/exiting, Retry/Next and final Win sequencing.
Exit/re-enter Play to confirm QA values reset and Levels 1–6 retain their defaults.

No Unity batchmode, GUI automation, external dependency, commit or push was used.
